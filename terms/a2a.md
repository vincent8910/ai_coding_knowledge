# A2A（Agent-to-Agent）— AI 彼此溝通的協作方式

> **白話說：** MCP 解決「AI 怎麼連工具」，A2A 解決「一個 Agent 怎麼找另一個 Agent 合作」。

---

## 它到底在解決什麼問題？

當工作不再由單一 AI 完成，Agent 需要能夠：

- 宣告自己能做什麼
- 接收另一個 Agent 的任務
- 回報進度與結果
- 處理需要人工確認的步驟
- 支援長時間任務、取消與失敗

A2A 是描述這類 Agent 對 Agent 協作的概念與協議方向。實際支援、版本與互通性仍應以官方規格和各工具文件為準。

## 和 MCP 的差異

| 關係 | 主要用途 | 例子 |
|---|---|---|
| Agent ↔ Tool | MCP：連接工具、資料與資源 | AI 呼叫瀏覽器或查文件 |
| Agent ↔ Agent | A2A：委派與協作 | 研究 Agent 把結果交給寫作 Agent |

## 不要把它誤解成

- 多個模型在同一個 prompt 裡輪流發言
- 只把 API 名稱改成 Agent 就算互通
- 不需要權限、身份、驗證與結果格式的自由聊天

真正可維護的 A2A 系統仍需要身份驗證、能力描述、權限邊界、逾時、重試與可觀測性。

## 目前閱讀方式

A2A 適合先當作架構概念理解；規格與實作快速演進時，請標明版本與官方來源，不要把草案或單一產品能力寫成所有 Agent 都支援的標準。

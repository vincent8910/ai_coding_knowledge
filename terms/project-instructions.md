# 專案指令檔（CLAUDE.md / GEMINI.md）— 讓 AI 自動記住你的專案規則

> **白話說：** 專案指令檔就像辦公室的**新人入職手冊**——新員工第一天到職，翻開手冊就知道公司的規矩、流程、禁忌。AI 讀了這份檔案，就自動知道你的專案規則。

---

## 它到底是什麼？

每次你叫 AI 幫你做事，是不是常常要重複交代一堆規則？

- 「用繁體中文」
- 「程式碼風格要用 4 格縮排」
- 「不要自動 push 到遠端」
- 「這個專案用的是 React，不是 Vue」

**專案指令檔就是把這些規則寫成一個檔案，放在專案資料夾裡。**

AI 每次開始工作，都會自動讀這份檔案，就像新員工第一天先讀公司手冊一樣。

## 不同的 AI 工具用不同的檔案名稱

| AI 工具 | 指令檔名稱 | 放在哪裡 |
|---------|-----------|---------|
| Claude Code | **CLAUDE.md** | 專案根目錄 |
| Google Antigravity | **GEMINI.md** 或 **AGENTS.md** | 專案根目錄 |
| Cursor | **.cursorrules** | 專案根目錄 |
| GitHub Copilot | **.github/copilot-instructions.md** | .github 資料夾裡 |

雖然名字不同，但概念完全一樣：**一份讓 AI 讀的規則說明書。**

## 裡面都寫些什麼？

以下是一些常見的內容範例：

| 類型 | 範例內容 |
|------|---------|
| **語言偏好** | 「所有回應和 commit message 用繁體中文」 |
| **程式風格** | 「用 TypeScript，不要用 any 型別」 |
| **專案架構** | 「前端在 /src，後端在 /server」 |
| **禁止事項** | 「不要自動刪除任何檔案」 |
| **比喻系統** | 「MCP 比喻為感官器官、Skill 比喻為專業證照」 |
| **工作流程** | 「每個任務獨立一個 commit」 |

## 生活比喻

| 情境 | 沒有指令檔 | 有指令檔 |
|------|-----------|---------|
| 新員工到職 | 每天問「公司幾點上班？」「報告格式是什麼？」 | 翻開手冊就知道所有規矩 |
| 請代班同事 | 每次都要從頭交代所有事 | 丟一份 SOP 文件，對方照著做 |
| 多人協作 | 每個人教 AI 不同的風格，成果亂七八糟 | 大家用同一份指令檔，AI 產出風格一致 |

## 為什麼團隊應該用指令檔？

1. **一致性**：不管誰用 AI，產出的東西風格一致
2. **效率**：不用每次重複交代規則
3. **可傳承**：新成員進來，AI 自動知道團隊規矩
4. **版本控制**：指令檔可以跟著專案一起用 [Git](git.md) 管理，改了什麼一目瞭然

> 💡 **小提醒**：你現在正在看的這個專案，就有一份 CLAUDE.md 在運作！裡面規定了語言要用繁體中文、比喻系統要一致、commit message 的格式等等。
